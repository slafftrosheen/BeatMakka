## Rulings

- Scope is phase A. Phase B's editable take capture is not implemented or represented by a disabled placeholder.
- The first spotlight supports constant-tempo sources. Variable-tempo music stays playable in Practice/Full mode; a spotlight request is explicitly rejected rather than changing its tempo.
- Pick the nearest duration to the 30-second design target among 4/8/12/16/24 bars. Finished-song excerpts never exceed their source; shorter Songs use their actual available bars. A loop may repeat. This is a game bound, not a platform limit.
- The chosen snapshot plus up to three same-tempo sequence variations are pinned at preparation. Live performance edits never mutate source music, save state or earned progress.
- Queue changes with a 0.35-second minimum scheduling lead. Cancellation is allowed only before that cutoff. This does not guarantee network arrival or sample-accurate audio.
- Layer mutes prevent subsequent triggers; already-playing one-shot tails finish normally. No new audio engine or microphone capture.
- Authored NPC requests are not player votes or popularity. Challenges are optional and award no currency or persistent flags; each condition counts at most once per set after a sustained bar.
- User owns local assets/builds/acceptance; all code in this batch is implemented here. AGENTS.md disallows running/adding tests absent a request, so verification remains source/static and remote delivery only.

## Implemented boundaries

`StreetSet` classifies roles from the actual resolved sample (including canonical/explicit local discovery mappings), not the visible physical pad. It builds one finite ordinary playback schedule from a bounded bar timeline. The original source identity, samples, sound settings, gains and routes are retained. Repetitions and excerpt boundaries are explicit; unavailable/muted source events are not invented. A transition preserves all preceding timestamps and notes. The same schedule consumer handles the result.

`StreetPerformance` pins the chosen source and compatible alternatives at preparation, checks epoch/revision on every action, and allows one pending transition. It publishes future schedule changes immediately with a minimum lead. Cancel restores the pre-change future only before the cutoff; late or duplicate requests are rejected explicitly. Sequence changes start the chosen pinned sequence at bar one. Role changes preserve its phase. The final complete bar remains the ending; no transition is accepted beyond it.

The three NPC request conditions use actual accepted note/layer differences, not aesthetic scoring: keep hook notes while removing another sounding layer; restore bass after a full muted bar; retain harbour notes while removing a competing sounding layer. Several rhythms, source variations and supporting-layer choices can satisfy them. Natural sparse-bar differences without an associated mask/source change do not count. A condition is evaluated after its affected bar ends and can count only once. Missing source roles make a request unavailable, never mandatory for completing the set.

An opted-in listener can offer one supported request per set. There is one pending suggestion, an eight-second global request cooldown, and at most four suggestions per set. Accepting changes the displayed request, not the performer's mix; ignoring does nothing to music. Only the performer can queue/cancel layer or source changes. Existing MusicService rate, payload, ownership/membership and distance checks remain in the path. No new RemoteEvent is added.

`ListeningSession` and `StageQueue` retain the single shared stage queue, voluntary join, expiry/turn offer, Stop/Leave, death/range/disconnect handling and existing courtyard quest boundary. Queue entries now retain their own physical venue. The already-existing street podium opens the board. The original quick courtyard Practice/Full path stays available; spotlight participants use the board so an excerpt cannot be mislabeled as a full Song by the older compact listening panel.

`StageView` retains the public constructor/update/destroy API and existing native widgets/skin. Its fixed controls now expose source selection, explicit performance mode, pinned duration, queue, current/queued layers, compatible variations, requests, acceptance/ignore and finish/interruption result. Controls are allocated once; the body scrolls while Sound, Leave and primary stage actions remain outside it. Results are session-local feedback, not saved completion, real votes or fans. Leaving to edit uses the existing station/Roamer return path; no source music is overwritten or automatically saved.

`SchedulePlayback` accepts a server-owned `futureOnly` flag for spotlights: unchanged prefix notes keep their cursor when a future change/cancellation arrives. Ordinary editor changes retain their old cursor protection. Source review also identified an existing finite-tail bug: the `finish <= last` return ran before the tail deadline, making final stop unreachable once the cursor reached musical duration. The deadline now runs first and stops voices once. This correction has not been runtime-tested here.

## #13 first-slice scene connection

The existing `QuayPublicBeat` signal now includes compact per-bar presentation frames for a spotlight. `QuayMusicField` selects the accepted frame from synchronized musical time, without waiting for a server tick. Existing QuayNeighbors animation/energy/change detection consumes it; no new crowd engine, duplicate audio, cutscene or personal-restoration mutation is introduced. Silent/muted bars remove that public source from the field; queued cancellation restores its original future frames. The reduced-effects path remains the existing neighbor enable flag. An individual listener's mute affects their audio, not the shared accepted timeline.

This implements the first causal part/scene connection, not all of #13. New dock/helper/climax signatures and six-phase chapter integration remain future code work. Existing chapter machinery is unchanged.

## Storage, lifecycle and limitations

No profile schema, DataStore key, asset binding, source pack or earned-progress field changes. Stage state, role masks, suggestions and results are ephemeral. Original project/saved Song snapshots remain untouched after finish, Stop, leave, lost focus, range exit or disconnect. Phase B take capture is still separate code work; there is no placeholder claim that a take has been saved.

Timing is bar-aligned within the existing frame-based audio path, not sample-accurate. The 0.35-second lead is a design margin, not a guaranteed network-delivery bound. Late packets/load failures remain possible and need actual device/listening acceptance. A server tick may acknowledge an already-scheduled transition later; the UI displays that state and disables new edits until acknowledgement rather than silently replacing pending work. Local Studio preview sources retain their pending-approval labels. Variable-tempo sources are rejected for Spotlight and remain available through the unchanged Practice/Full schedule path.
