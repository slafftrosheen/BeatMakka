# Issue #17 — A quiet dock wakes up

The same-crate prompt is an untimed, solo-capable activity over the ordinary musical project. It selects six canonical sounds from the current kit: A01, A05, A09, B01, C01 and D10 (absolute pads 1, 5, 9, 17, 33 and 58). It neither copies a pack nor changes source audio, admission or version identities.

## Musical contract

`CrateChallenge` exports `Id = "quiet_dock_v1"`, `Version = 1`, `Bpm = 174`, `SectionBars = 4`, `TotalBars = 8`, the prompt title/description, `PalettePads`, `Modes`, `palette(unlocked)`, `create(id, mode, unlocked)` and `review(project, unlocked)`.

Creation returns `project, nil, selection` or `nil, problem`. The project contains two ordinary independently editable Sequences, Quiet dock and Arrival, and an ordinary Draft Song arranging each once, in that order. Its full normal 64-pad kit and pack/version pins remain intact. The crate restricts authored notes in these two sections; it does not create a second instrument or hide the full editor.

The only project marker is:

```lua
project.challenge = {
    schema = 1, promptId = "quiet_dock_v1", version = 1,
    quietId = quiet.id, arrivalId = arrival.id, draftId = draft.id,
    mode = "blank", -- or "steady" / "offbeat"
}
```

Blank starts with no notes and remains available when canonical audio exists but is not ready. The two examples require all six displayed sources to be available before creation. Missing identities, mapping mismatches or unavailable example sounds fail explicitly before activation; no substitute is selected.

The authored steady example starts with sparse texture/hat notes and introduces a straight drum pulse, bass and a vocal. Its offbeat alternative starts with sparse displaced bass/texture notes and answers with syncopated drums, bass and vocal/harbour accents. Both keep the same tempo, duration and palette, with visibly different note positions and velocities. `create` validates each complete candidate and, for examples, requires the same pure structural review used for player compositions. This is a source-data guarantee, not a human musical-quality or listening acceptance result.

## Concrete review

`review` returns `present`, `passed`, ordered `checks = { { ok, label, fix } }`, the first useful `hint`, the displayed per-sound `palette`, source IDs, a typed current `ref = { kind = "song", id, revision }`, duration/bar counts and `localOnly`. It also exposes `quietSamples`, `quietOnsets`, `arrivalSamples` and `arrivalOnsets` for explanation.

Checks require the exact prompt metadata, a valid ordinary project, two four-bar sections at 174 BPM without tempo maps, and the intentional Quiet dock → Arrival two-step/eight-bar arrangement with one repeat each. Every authored note in those sections must reference one of the six canonical sample IDs, including muted notes. Other work elsewhere in the project is not graded.

The ordinary Transport resolves both sections and the draft with `requireReady = true`. Missing sounding sources and mismatched version pins refuse preview, while unavailable unused palette entries remain visibly unavailable. Existing track/sequence/pad/event mutes, solo state, track/pad gains and positive note velocity determine which scheduled notes count as sounding. Quiet dock needs one or two different sounding samples; Arrival needs at least three and more distinct note-start positions. Several notes stacked at the same tick count as one start. Both sections need sounding notes.

These are inspectable prompt requirements. They do not judge originality, groove, taste, acoustic output, loudness or artistic quality. Performed audio/listening and target-device acceptance remain separate.

## Server transaction and preview lifecycle

`CrateChallengeService.new(profiles, send, persist, owns, core, present)` supplies `summary(player)`, `command(player, action, request)`, `tick()` and `remove(player)`. `owns(player)` must enforce the existing nearby owned-instrument/activity boundary. `core` is `MusicWorkspaceCore`; `present(player, ref)` is the injected existing short-presentation route and returns `ok, message`.

Start, Review, Preview and Present require `request.context = { projectId, revision, generation, editVersion }` matching the current workspace exactly. Commands return `ok, message`; the caller projects/sends the resulting state. Start also takes `mode`. Stop has no stale-context dependency, and Close only changes optional guide-panel state.

Start clones the entire current music document, preserves the prior exact project through `WorkspaceState.preserve` (except an untouched factory workspace), installs the candidate only in the proposal and passes `ProfileStore.capture` before the single `WorkspaceState.activate` commit point. Full archive/storage/readiness failures preserve originals. Finished Songs, imports, recovery data and earned progress stay in the surrounding document. Nothing auto-saves or auto-finishes; normal edits, undo/recovery and explicit Save/Finish continue to own those operations.

Preview selects the challenge draft through ordinary `SongSelect`, then starts ordinary `SongPlay`. Resolvable drafts that still need structural changes can be heard as practice. Recognition requires a passed structural review at preview start and again at its full ending. The service pins the exact project object/revision, workspace generation/edit version, transport object, schedule, epoch, typed draft revision, start anchor and zero offset. It checks continuing ownership, nonloop playback, no recording/queued transition, and monotonic position through the schedule's `completeAt`, including the existing bounded audio tail.

`tick()` must run **before** `MusicWorkspaceCore.tick()` in the existing 0.1-second service loop, so the service sees a naturally ending transport before Core stops it. Manual Stop, pause/resume/seek, a source/workspace/context change, different transport/epoch, lost ownership or departure invalidate the attempt. Stop/remove clean up only the tracked preview transport; an unrelated replacement transport is not stopped. Closing the guide does not stop playback. A delayed timer or request alone grants no recognition.

`summary` returns `schema`, `promptId`, `version`, title/description, tempo/length/palette, current `review` and `context`, `open`, `previewing`, `previewCompleteExact`, `recognized`, `saveMode` and `saving`. It recomputes review from current work and exposes full-preview completion only while its exact eligible workspace still matches. An incomplete practice preview does not become a completion certificate.

## Recognition, presentation and comparison boundaries

Recognition sets only the existing `profile.identity.awards["activity:same_crate"]`, once per profile. The shared identity whitelist supplies the bounded 20 Beatmaker / 10 Listener XP mapping. A new award increments `editVersion` but does not start a save. Recognition and the Draft remain unsaved until the player uses the ordinary explicit Save action; the UI distinguishes unsaved recognition from an acknowledged snapshot. There is no second reward ledger, popularity score, currency or repeatable farming payout.

Present requires a passed current structural review, then passes its typed Draft Song reference to the injected #22 short-set integration. It does not turn the draft into a Finished Song, overwrite its source or require editable take capture. Any same-server comparison is an explicit link/invitation through the existing #23 record/release flow, with its source, permission, title-filtering and ownership rules. No matchmaking, global ranking, new messaging, vote or audience-size progression gate is introduced.

Voluntary listening, comparison and another attempt still require actual observation, distinguished from required guidance. Neither a structural pass nor a scheduled full preview establishes enjoyment, human listening, actual device timing, final audio approval, hosted save durability or release readiness.

Only source review was performed for these new modules. No gameplay tests, Studio/device/listening run, build, dependency, paid call, asset change, upload, publication or commit was performed.
