## File boundaries

`SoundHunt.luau` derives the actual sample from `SampleCatalog.discoveryFor`, locates its existing program pad and produces versioned request packets. It does not fall back to retired/test audio or reinterpret a legacy pattern slot as a bank. Optional exercise comparisons use MusicSequence's PPQ and bar length.

`DiscoverySession.luau` accepts only DiscoveryPreview and DiscoveryAdd. Collection and declared playback readiness are checked server-side. Insert requests must still match station, project/revision, workspace generation, edit version, sequence and track. Bar/step bounds are checked. A duplicate note at the same pad/tick is rejected rather than doubled or overwritten. Missing mappings require the player's explicit ordinary sound-assignment action; the feature never replaces another sample to make room. Recording must be stopped before guide insertion. A normal pending save does not disable ordinary edits; the existing persistence revision protection remains authoritative.

The pre-existing workstation implementation is moved byte-for-byte from `MusicWorkspace.luau` to `MusicWorkspaceCore.luau` (original blob `6d5e621354827f37006a40bf7e9984c6d7fcf74d`). The public MusicWorkspace module keeps the same API and delegates all old commands unchanged; it routes only the two new discovery commands to their focused handler. This keeps input, transport, undo, First Groove and save transactions in one implementation rather than rebuilding them inside the encounter.

`RecorderGuide` now accepts an optional action API. Its controls are built once, selectable and reflow between one/two columns with 44-pixel rows. In the live editor it shows one source card at a time. The physical performance pads remain outside the scrollable editor. Back to Notes is view-only. The current bar is taken from the ordinary sequence editor; there is no separate step buffer or sequencer.

`NeighborhoodMissions` continues to evaluate the exact captured saved document; only ProfileStore's accepted write merges awards. Echo results never reach that ledger. Existing valid earned flags remain true. `DiscoveryCatalog.use` now describes the creative interaction; the old Studio-binding exercise text is retained as `legacyUse`, not imposed on the new sound-hunt action.

## Musical freedom and evidence

Dock completion accepts any two distinct audible positions, not one prescribed beat. For example, positions 1/7 and 4/13 are different eligible rhythms within a bar. The optional dock echo is 1/4/9/12; neither example has to copy it. Vent requires its sound together with metal; helper requires two saved sequences with different chirp positions. These are explicit structural/action rules, not an assessment of musical quality.

The echo reference requests the unprocessed authored source through the existing GuiFactory cue connection and AudioEngine. It uses bounded local delayed callbacks, not a new audio engine or network timing score. Labels say playback was requested, not heard or latency-verified. The grid comparison only compares note positions. A missing or muted local audio output is not reported as a successful listening exercise.

Source availability can still depend on the current Studio-only substitute bindings. The guide labels those explicitly. No readiness/admission/listening flags, asset IDs or pack contents are changed.
