# Issue #15 — credited Back-to-Back joint Draft copies
Date: 2026-11-04. Base: `e39d00074e97b6e9d7e7d785ab61217d59b37d1c`.

## Purpose and decisions
After the invited/role-filtered two-person jam (#15, preceding commit), two actual contributors can mutually authorize a private **current shared phrase** copy. Each can independently Keep that copy as a new editable ordinary Song Draft inside their own workspace, or Discard it. Neither musician can write the other's project or saved library, and no release or Finished Song is created automatically.

This is deliberately a capture of the **currently pinned roles** at the next common bar, not a recording of every change that occurred earlier in the session. Such a historical performance-take capture is a different capability (#22 phase B for solo Spotlight). Source contribution versions must be settled, with no pending publication, tempo or role swap. A role missing from playback, unavailable sound, incompatible off-grid phase, or phrase requiring more than 64 bars is refused without shortening.

## Server flow
1. Either active member selects OFFER JOINT COPY, creating one expiring consent offer. The other must ACCEPT or DECLINE. New or stale invites and detached members cannot author a copy. The offer carries pinned source-version identities and shared BPM.
2. On acceptance the server validates both currently accepted role snapshots, builds one bounded private phrase with exact original source identities and current logical phase for the next shared bar, and places **independent** temporary copies in the two contributor profiles. The copy is not part of persistent profile schemas or the normal save. Disconnect loses a temporary, unkept copy.
3. After leaving the jam, each individual owner can choose KEEP AS DRAFT or DISCARD TEMPORARY. Both use a short two-press UI confirmation bound to copy ID, project identity, revision, edit version and workspace generation. The server validates the private copy ID and context again. The private operation is independent of unrelated global jam revisions after leaving.
4. KEEP builds a candidate in memory and validates the standard full project and profile budget before mutating anything. Every participating source track and its 64-pad program are deep-copied into new IDs. Source parts are aligned to the accepted bar and repeated to a supported common-cycle length, creating one new combined Sequence and one ordinary draft Song with two credited contributors. Normal transports and sound settings apply. Existing tracks/sequences/drafts/finished songs/archive/recovery remain unchanged; project copy admission is one Undo step with Redo support.
5. The standard MusicTransport resolves the candidate Draft and compares every remapped event by ID, tick, time, sample, pad, velocity, duration, pan, track, and sound settings. If the proposed replay differs, or budget/audio unlock requirements fail, Keep rejects the entire operation and retains the temporary copy. This is an in-code data-integrity guard, **not** an executed acoustic test. Because imported music uses normal playback volume, the performer still reviews the combined mix before public release.
6. On success the Draft is selected; its metadata and both contributor credits are retained by the existing music schema/import. The UI states **UNSAVED DRAFT** and directs the player to Song Mode to review, edit, and explicitly Save. It never calls ProfileStore.save, never marks a finished Song, and never uploads audio.

## Files and contracts
- `src/shared/JamCollaboration.luau`: deterministic one-phrase compiler and transactional materializer. No saved-state or client authority.
- `src/server/JamCopySession.luau`: private pending copy/receipt, context-matched Keep/Discard, full-profile capture, undoable commit.
- `src/server/JamService.luau`: consent offer/answer, settled-source preconditions, private copy retention, independent personal post-jam management.
- `src/client/JamView.luau`: native offer/answer, private temporary status, contributors, confirmed Keep/Discard and clear save boundary.
Other source modules, pack identities, 64 pad semantics, original sound clocks and the profile/DataStore format are unchanged.

## Limits and release boundaries
The LCM of source sequence lengths must fit the existing 64-bar ordinary Sequence limit. Source phases must be aligned to the shared bar within a small tick tolerance; off-grid phrases are refused rather than requantized. Required source samples must be playback-ready to the importing player under their own unlock/permission policy. Program/track/event/sequence/draft byte budgets are all enforced by ordinary project validation, not pruned automatically. Same-time note ordering is preserved deterministically by the imported track/event ID order, but exact cross-owner choke/acoustic behaviour must still be measured on devices. Cooperative mix headroom remains a human audio acceptance issue; source gains are not secretly changed.

Credited copies are session-local until Keep and *still unsaved* after Keep. Only the existing Save action provides a session/cloud acknowledgement, subject to #10 hosted evidence. No network/cloud persistence, microphone recording, third-party packs, additional audio streams, CI/test runners, Roblox upload, Experience publishing or unapproved spend was added.
