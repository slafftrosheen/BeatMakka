## Keep, go to Studio, save, play

After an imported unsaved take, the finish panel now highlights Studio with a save picture and a short Save at Studio cue. Again and Out stay available. Keep/Discard confirmation, materialization, Undo/Redo, song ownership and explicit saving remain unchanged.

A deliberate StageStudio request can carry a local, fifteen-second navigation intent for the currently selected imported take. It binds the take ID, draft ID, project ID and workspace generation. Only arrival at a station with the stage closed, the exact draft still selected, and no active record/jam consumes it. Changed context, expiry or StageClose cancels it. The existing server still owns studio/range/occupancy checks. No song/draft is selected behind the player's back, and no Save or Play command is generated by this handoff.

On matching arrival the Song page opens. A save picture and outline identify the existing Save key. While a save is pending the picture changes to waiting; the guide switches to a check and outlines Play only when the existing server take summary and matching draft saved revision acknowledge saving. Session storage remains visibly labelled Session; unavailable storage says Retry and existing detailed notices remain. The small picture occupies the inactive clock space, preserving contributor credits and the arrangement overview. During playback the clock returns. Changing away from the matching take removes this guide. Save and Play still require explicit presses and use their unchanged music/profile contracts.

Controller arrival focuses Play if saving was acknowledged during travel, otherwise an enabled Save key, otherwise the Drafts control while a save is pending. If a focused Save key becomes unavailable during the guided save, focus moves to the usable Drafts control rather than remaining on a disabled action.

## Collected versus worn

Fair reward previews now show a bag and a separate item after server-acknowledged collection. The check and item attached to its avatar/Roamer picture appear only when the equipped reward ID also matches. Uncollected previews remain unowned. Rows and receipts use the same authoritative ownership/equipment values. The receipt's Wear action uses a hand picture; collection alone no longer looks like completed wearing. No claim, equip, coin amount, save or destination action is automatic.
